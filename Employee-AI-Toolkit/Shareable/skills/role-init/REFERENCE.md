# Role Init — Reference

## Role-Specific Project Questions

Used by `/project-init` during its Step 4 interview. Identify the matching role by heading and apply those questions. If no question set exists for the role, use the standard questions only.

---

### Technical-Director

Ask when setting up a Technical Director project:

1. Is this a board-level deliverable, an internal initiative, or both?
2. Which departments, teams, or stakeholders are affected beyond your own function?
3. Is there a board deadline, reporting milestone, or Ops Board decision point driving this?
4. Does this require budget — is it within existing allocation or does it need a business case?
5. Which of Saturn's business functions does this primarily support? (Create Value / Deliver Value / Finance & GRC — or cross-function?)
6. Does this intersect with any compliance, ISO 27001, or security obligations?

---

### Compliance-Officer

Ask when setting up a Compliance Officer project:

1. Which framework or control area is this driving? (ISO 27001 clause, Cyber Essentials control, GDPR obligation, Annex A control?)
2. What is the trigger — surveillance audit, renewal, incident, internal gap, or proactive improvement?
3. Which departments, systems, or processes are in scope?
4. Is there a regulatory, certification, or audit deadline?
5. Will this produce evidence artifacts that need to be retained? If so, where will they live?
6. Is there an open risk register item, nonconformity, or corrective action this resolves?

---

### Product-Officer

Ask when setting up a Product Officer project:

1. Which part of SaturnVision or the product suite does this relate to?
2. Who are the primary users — internal team, external clients, or both?
3. What is the measurable success criterion — how will you know this is done and working?
4. Is this on the current roadmap or a new initiative requiring prioritisation discussion?
5. What are the key dependencies — platform services, client commitments, infrastructure, or third-party?
6. Is there a client-facing release date, demo, or contractual milestone attached?

---

### Systems-Architect

Ask when setting up a Systems Architect project:

1. Which Azure services, infrastructure components, or architectural layers does this affect?
2. Is this greenfield design, a migration, or an improvement to an existing system?
3. What are the security requirements — ISO 27001 controls, network boundaries, data classification level?
4. What is the expected scale — devices, users, data volume, throughput targets?
5. Are there Azure cost constraints or spend targets for this work?
6. Who needs to sign off on the design — Technical Director, DevOps team, security review panel?

---

### IT-Manager

Ask when setting up an IT Manager project:

1. Which internal systems, services, or user groups does this affect?
2. How many users or devices are in scope?
3. Is this reactive (fixing a problem) or proactive (planned improvement or rollout)?
4. What is the support implication after delivery — ongoing burden, SLA change, runbook or documentation needed?
5. Is there an M365 or Azure AD dependency that requires tenant-level changes?
6. Is there a business continuity or downtime risk during implementation — and if so, what is the mitigation?

---

### Developer

Ask when setting up a Developer project:

1. Which codebase or service does this touch? (SaturnVision, SaturnGuard, internal tooling, client project?)
2. What is the tech stack for this work? (.NET/C#, TypeScript, Azure Functions, other?)
3. Is this feature work, a bug fix, a refactor, or an infrastructure change?
4. What is the testing approach — unit, integration, manual, E2E?
5. Is there a PR review, architecture sign-off, or security review required before merge?
6. What is the deployment path — CI/CD pipeline, manual release, or hotfix?
