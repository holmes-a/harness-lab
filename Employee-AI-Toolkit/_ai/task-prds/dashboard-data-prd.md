# PRD: Project Dashboard Data Layer

## Purpose

A machine-readable index of all AI-engaged projects across the Saturn workspace, designed to power a future single-page dashboard. The index does not replace Monday.com — it captures the AI-engaged subset only. The gap between Monday and this index is the AI adoption signal.

## Scope

**In scope:**
- `projects.json` — the data file, workspace root
- Updates to `project-init` — register new projects on creation
- Updates to `project-wrap-up` — stamp `last_worked` at session end
- JSON schema definition

**Out of scope:**
- The SPA dashboard (separate future project)
- Session-start navigation / name-to-path mapping (separate task)
- Non-AI projects — Monday.com is the source of truth for those

## Data File

**Location:** `projects.json` at workspace root  
**Format:** Flat JSON array of project objects — no nesting  
**Consumer:** SPA reads directly; Claude writes only (never reads for display)

## Schema

```json
{
  "id": "unique identifier — generated by project-init at creation",
  "name": "human-readable project name",
  "role": "role folder name — e.g. Technical-Director",
  "path": "relative workspace path — e.g. Technical-Director/Employee-AI-Toolkit",
  "type": "Ongoing | Defined Goal",
  "status": "In Progress | Blocked | Completed - Goal Reached | Completed - Partial | Completed - Abandoned",
  "start_date": "YYYY-MM-DD — set by project-init",
  "deadline": "YYYY-MM-DD — optional, Defined Goal projects only",
  "last_worked": "YYYY-MM-DD — updated by project-wrap-up"
}
```

## Field Notes

**type**
- `Ongoing` — no fixed end state; sits at role root alongside Defined Goal projects
- `Defined Goal` — regular project folder; has a defined completion condition

**status**
- `In Progress` — actively being worked on
- `Blocked` — work has stalled on an external dependency or decision
- `Completed - Goal Reached` — defined goal was met
- `Completed - Partial` — project closed with partial success
- `Completed - Abandoned` — project closed without reaching the goal

**deadline** — only present for `Defined Goal` projects; omitted (not null) for `Ongoing`

**id** — format TBD (see Blocked On); must be stable across renames

## Maintenance Model

| Event | Action |
|---|---|
| New project created | `project-init` appends a new record to `projects.json` |
| Session ends | `project-wrap-up` finds the active project record by `id` and updates `last_worked` |
| Project archived | Record updated: status set to a `Completed` value; SPA filters archived projects by status |

Neither skill requires a new user habit — both integrate into existing flows.

## Blocked On

The following must be resolved before implementation can begin:

1. **Unique project ID** — no stable identifier exists in the current scaffold. `project-init` must generate an ID and write it into the project `CLAUDE.md`. Without this, `project-wrap-up` cannot reliably match records. See finding: *Projects have no guaranteed unique identifier*.

2. **Type & status controlled values** — the values above are proposed; need confirming and wiring into `project-init` prompts and `project-wrap-up` update logic.

3. **`_archive` folder location** — currently at workspace level; should move to role level before the archive/completion flow is built. See tasks: *Project Metadata — Schema & Values*.

4. **Skill updates** — `project-init` and `project-wrap-up` currently have no type, status, or JSON-writing logic. Both need auditing and extending.

## Future Work

- **Session-start navigation** — lightweight name-to-path mapping; separate task
- **Backfill** — existing projects pre-dating this system will need manual or scripted entry into `projects.json`
